Fundamentos

Fundamentos de IoT Industrial

La automatización industrial mediante IoT integra sensores, actuadores, conectividad y software para que las máquinas y procesos se monitoreen y controlen de forma remota, en tiempo real y con mínima intervención humana. A continuación se presentan los cinco pilares conceptuales del ecosistema IoT industrial.

Sensores

Miden variables físicas (temperatura, humedad, presión) y las convierten en señales digitales.

  • Analógicos (termistores) y digitales (DS18B20, DHT22).
  • Calibración periódica para mantener precisión.
  • Conectados a microcontroladores por GPIO, I²C o SPI.

Actuadores

Ejecutan acciones físicas (motores, válvulas) a partir de órdenes recibidas.

  • Relevadores, servomotores, válvulas solenoides.
  • Controlados por señales digitales o PWM.
  • Aislamiento óptico recomendado para proteger el controlador.

Gateways

Conectan los dispositivos de campo con la nube o el dashboard local.

  • Traducen protocolos: Modbus, LoRaWAN → MQTT, HTTPS.
  • Almacenan datos ante caídas de red (buffering).
  • Pueden ejecutar Edge Computing para filtrar datos.

MQTT

Protocolo ligero de mensajería que distribuye los datos desde los sensores hacia los consumidores.

  • Modelo publish/subscribe con un broker intermediario.
  • Tópicos jerárquicos: fabrica/linea1/sensor/temp.
  • Niveles QoS 0, 1 y 2 según fiabilidad requerida.

Dashboards

Visualizan los datos en tiempo real y permiten tomar decisiones informadas.

  • Herramientas: Grafana, Node-RED, ThingsBoard.
  • Indicadores, gráficas, medidores y alarmas visuales.
  • Accesibles desde web o app móvil con autenticación.

Casos prácticos

Cuatro escenarios reales de automatización industrial con IoT. Haz clic en cada caso para expandir el detalle, revisar el código de referencia y probar las demostraciones interactivas.

1

Monitoreo de temperatura

Publicación periódica de lecturas de sensor vía MQTT.

Un microcontrolador (por ejemplo ESP32) lee un sensor DS18B20 cada cierto intervalo y publica el valor en un tópico MQTT. El dashboard se suscribe a ese tópico y grafica la temperatura en tiempo real, permitiendo detectar anomalías sin estar presente en la planta.

publicar_temperatura.py
# Publicar temperatura cada 5 segundos vía MQTT
import paho.mqtt.client as mqtt
import time, random

broker = "broker.hivemq.com"
topic  = "fabrica/linea1/sensor/temp"

client = mqtt.Client()
client.connect(broker, 1883)

while True:
    temperatura = round(random.uniform(22.0, 35.0), 1)
    client.publish(topic, temperatura)
    print(f"Publicado: {temperatura} °C")
    time.sleep(5)
2

Control de actuador

Suscripción a un tópico para activar un relevador.

Un actuador (relevador conectado a una bomba o motor) escucha comandos desde el dashboard. Cuando se publica "ON" en el tópico fabrica/linea1/actuador/bomba, el microcontrolador activa el pin GPIO correspondiente. Esto permite gobernar equipos físicos de forma remota.

control_actuador.py
# Suscribirse y activar relevador según el comando recibido
import paho.mqtt.client as mqtt
from gpiozero import OutputDevice

rele = OutputDevice(17)  # GPIO 17
topic = "fabrica/linea1/actuador/bomba"

def on_message(client, userdata, msg):
    comando = msg.payload.decode()
    if comando == "ON":
        rele.on()
        print("Bomba ACTIVADA")
    elif comando == "OFF":
        rele.off()
        print("Bomba DETENIDA")

client = mqtt.Client()
client.on_message = on_message
client.connect("broker.hivemq.com", 1883)
client.subscribe(topic)
client.loop_forever()
3

Alerta por umbral

Demostración interactiva de alarma por temperatura crítica.

Define un umbral de temperatura máximo permitido. Una simulación actualiza el valor del sensor cada 2 segundos. Si la lectura supera el umbral, se dispara una alerta visual en tiempo real; de lo contrario, se confirma que el proceso está dentro del rango normal.

Buenas prácticas

Seguridad y buenas prácticas

Un sistema IoT industrial expuesto puede comprometer equipos, datos y personas. Estas prácticas reducen el riesgo y aumentan la confiabilidad operativa.

Cifrar la comunicación con TLS entre dispositivos, gateway y broker.
Usar credenciales únicas y contraseñas robustas por dispositivo.
Segmentar la red industrial (OT) de la red corporativa (IT).
Actualizar el firmware de los dispositivos de forma periódica.
Aplicar el principio de mínimo privilegio en usuarios y servicios.
Registrar y monitorear eventos críticos en una bitácora centralizada.
Definir un plan de respuesta ante incidentes y caídas del sistema.
Realizar copias de seguridad de la configuración y datos históricos.

Riesgos frecuentes

  • Dispositivos con credenciales por defecto sin cambiar.
  • Tráfico MQTT sin cifrar expuesto en redes públicas.
  • Falta de actualizaciones de firmware por meses o años.
  • Ausencia de registros para auditar qué ocurrió tras un fallo.
  • Dashboards accesibles sin autenticación ni control de roles.
  • Falsa sensación de seguridad al confiar únicamente en la red LAN.

La automatización IoT debe aumentar la confiabilidad del trabajo, no esconder errores ni reemplazar la responsabilidad del operador.
